## TOCTOU Race-Condition Audit: `gameStore.ts` & `socket.ts`

### Finding #1 (CRITICAL): Duplicate `init()` calls register duplicate socket listeners, causing double bet emissions

**Files:**
- `gameStore.ts:161-397` — the `init()` function that registers all socket listeners
- `App.tsx:40-42` — calls `init()` on mount
- `admin/RateControlPanel.tsx:216-218` — calls `init()` again on mount

**The Bug:**
Two components call `init()`: `GameApp` (main game) and `RateControlPanel` (admin panel). They are mutually exclusive (App.tsx:87 renders one or the other via ternary), but **navigating between `/` and `/admin` unmounts one and mounts the other**. Since `init()` calls `socket.on(...)` without ever calling `socket.off(...)` or `socket.removeAllListeners()`, every listener is registered a second time on the same socket. Socket.io-client's EventEmitter adds a *new* handler each time — it does not deduplicate.

**Concrete sequence that breaks:**

1. User visits `/admin` → `AdminPanel` mounts → `RateControlPanel` mounts → `init()` call #1 registers handlers A (15+ `socket.on` calls).
2. User navigates to `/` → `AdminPanel`/`RateControlPanel` unmounts (handlers A remain on the socket, never cleaned). `GameApp` mounts → `init()` call #2 registers handlers B for the **same events**.
3. When the server emits `round:betting`, **both handler A and handler B fire in sequence**.

**Breaking scenario for auto-bet panels:**

- Handler A runs: captures `prev = get().panels` (queued/autoBet flags from previous round), calls `set()` to reset panels, then `forEach` → auto-bet panel triggers `placeBet()` → emits `bet:place` (1st).
- Handler B runs: `get().panels` now has `autoBet: true` (preserved by spread in `set()`). `wantsBet = [false, true]` because `autoBet` is still `true`. `set()` resets panels again. `forEach` → auto-bet path: `prev[i].autoBet === true` and `p.amount <= s.balance` → calls `placeBet()` → emits `bet:place` **(2nd — duplicate)**.

Net result: the client sends two `bet:place` messages for a single intended auto-bet. If the server accepts both, the user is double-charged.

**Why every socket handler fires twice after the second `init()` call:**

| Handler | Effect of duplicate |
|---|---|
| `round:betting` | Auto-bet placed twice (above). Queued bets also re-emitted. |
| `tick:multiplier` | Auto cash-out guard (`cashOutPending`) prevents double-cashout for handler B, but the `set()` + `get()` cycle runs twice per tick. |
| `bet:accepted` / `bet:cancelled` / `bet:cashedout` / `bet:cashout_failed` | All state update logic runs twice per event. Mostly idempotent, but wasteful. |
| `init` (initial state) | Full state overwrite runs twice per connect. |
| `betLimits:update` / `balance:sync` | Redundant `set()`, harmless. |

**The root cause is the absence of listener lifecycle management.** The `init()` function (gameStore.ts:161) never calls `socket.off()` or `socket.removeAllListeners()` before registering, so it is not safe to call more than once. Two separate components independently call it, assuming it's idempotent — it is not.
